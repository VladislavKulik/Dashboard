# Этап 2 — Tasks и Project Details

## Что можно проверить в приложении

1. На Home нажать на «Задач» или открыть нижнюю кнопку добавления → Task.
2. На Tasks переключать фильтры: Все, Сегодня, Предстоящие, Выполнено.
3. Нажать поиск и отфильтровать задачи по названию.
4. Нажать на круг слева от задачи — статус изменится.
5. Добавить задачу через кнопку «Добавить задачу», задать название и приоритет.
6. В Projects открыть карточку «Мобильное приложение».
7. В Project Details посмотреть описание, прогресс, этапы и ближайшие задачи.
8. Отметить задачу на Project Details и проверить, что её статус изменился также в Tasks и Projects.
9. Открыть список задач проекта — Tasks должен показать только связанные с проектом элементы.

## Контракт экранов

`TasksScreen` принимает задачи, проекты и callbacks. Он не управляет хранилищем самостоятельно.

`ProjectDetailsScreen` получает выбранный проект и связанные задачи, а изменения передаёт через `onToggleTask`.

`ProjectsScreen` использует те же `DashboardProject` и `DashboardTask`, что и подробный экран.

## Временное хранилище

`DemoDashboardStore` хранит `SnapshotStateList<DashboardTask>` и предоставляет `toggleTask`, `addTask`, `projectById` и `tasksForProject`. Инстанс создаётся один раз на уровне `LifeDashboardApp`, поэтому состояние не теряется при навигации между экранами.

Это только in-memory реализация. Следующий логичный технический шаг после стабилизации UI — заменить её на ViewModel + Repository + Room. Не нужно переносить Compose state list внутрь Room Entity.
