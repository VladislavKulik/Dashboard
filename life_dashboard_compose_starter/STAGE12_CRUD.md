# Stage 12 — CRUD для задач и проектов

## Задачи

`TaskRepository` теперь предоставляет `updateTask()` и `deleteTask()` в дополнение к наблюдению, созданию и переключению статуса.

Редактор задачи позволяет изменить:
- название;
- срок (текстовую подпись);
- приоритет;
- категорию «Сегодня / Предстоящие»;
- связанный проект или снять привязку.

Перенос задачи между проектами, удаление задачи и корректировка счётчиков проекта выполняются в одной Room-транзакции. Удаление требует подтверждения. Записи `activity_events` сохраняются: удаление задачи не стирает историю уже совершённых действий.

## Проекты

`ProjectsRepository` получил `deleteProject()`. На экране Projects можно создать проект; на Project Details — изменить описание, срок, цвет и список этапов, удалить проект или переключить статус этапа.

Редактор принимает этапы построчно. Порядок этапов сохраняется отдельным полем `project_stages.sortOrder`, а статус существующих этапов сопоставляется по названию. Если список этапов переупорядочен или дополнен, совпавшие названия сохраняют свои статусы; новые этапы создаются незавершёнными.

При удалении проекта задачи не удаляются: их `projectId` становится `NULL`, а этапы и проект удаляются в одной транзакции.

## Изменение схемы БД

Версия Room повышена с 2 до 3:
- добавлено `project_stages.sortOrder`;
- в `MIGRATION_2_3` таблица tasks пересоздаётся с согласованным SQL default для `sortOrder`: это нормализует как базы, созданные Stage 11, так и базы, пришедшие через миграцию 1 → 2;
- добавлена миграция `MIGRATION_2_3`;
- цепочка `MIGRATION_1_2` → `MIGRATION_2_3` остаётся зарегистрированной;
- `@ColumnInfo(defaultValue = "0")` согласован с SQL default для `tasks.sortOrder` и `project_stages.sortOrder`, чтобы Room проверял одну и ту же схему до и после миграции.

## Границы этапа

CRUD привычек (переименование, смена цвета/напоминания, удаление) не включён в этот этап — его лучше выполнить отдельно, чтобы не смешивать два набора форм и операций. Настоящие системные напоминания пока не реализованы.

## Подключение

Архив содержит исходники `app/src/main/java/com/example/lifedashboard`. Скопируй их в соответствующий package существующего Android-проекта. Не создавай вторую базу вручную: `RoomDashboardPersistence` строит её с именем `life_dashboard.db` и регистрирует обе миграции.
